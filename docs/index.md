# The `python` targets — ctypes projection + spec input

`handl-plugin-codegen-emitter-python` provides two codegen targets
(PL-004):

1. **`python`** — `SdkgenModule` (from source `c`) → one `<module>.py`
   of `ctypes` bindings. The target record is
   `(source: "c", emitter: "python")`: it resolves `c` *by name*
   through the registry, so this repo never crate-depends on
   `codegen-c`.
2. **`python-spec`** — `.yaml`/`.yml`/`.json` inputs ride the
   `SpecModule` IR family (`Source<SpecModule>` = `SpecModule::load`,
   `Emitter<SpecModule>` = the embedded-CPython `.hnl` renderer) and
   emit `<package>/<package>.hnl`. The pre-PL-004 `spec_input` hook —
   an IR-free bypass that wrote files directly — is gone; spec inputs
   are a normal source/emitter pairing now. Because one target pairs
   exactly one IR family, spec inputs take the `python-spec` target
   name; input-kind routing on the `hnl codegen` command line is the
   T-076 command layer's job.

```bash
# ctypes projection of a C header:
hnl sdkgen python /usr/include/time.h --output out/ [--target …] \
    [--include '…'] [--exclude '…'] [--config c.sdkgen.yaml]

# spec-driven embedded-Python module (until T-076 routes by kind):
hnl sdkgen python-spec mymod.yaml --output handl-packages/generated
```

`--include`/`--exclude`/the C `.sdkgen.yaml` schema all pass through to
backend `c` (`source_filters: true`). No docs pass runs on the target —
the ctypes projection doesn't layer external docs.

## The ctypes emitter

`PythonEmitter::materialize` returns one `Change::text` for `<module>.py` (applied under `--output` by the kernel `Engine`). `build_module`
layout:

```python
# Generated by `hnl sdkgen python` from <module> — do not edit.
# backend: c  target: x86_64-unknown-linux-gnu
# source: <url>            # when --from-url was used

"""ctypes bindings for <module>."""

import ctypes

_lib = ctypes.CDLL("<module.library>", use_errno=True)   # "None" when library empty
```

then `# --- records ---` / `typedefs` / `constants` / `functions`
sections and a sorted `__all__`.

### IR → ctypes mapping

- `Record` → `class Name(ctypes.Structure)` reproducing declared offsets
  **exactly**: `_layout_ = "ms"` + `_pack_ = 1` (contiguous layout; the
  `ms` pin is what bare `_pack_` already meant and CPython 3.19+
  requires — 3.14+ rejects `_pack_` under gcc-sysv). Gaps become
  explicit `c_ubyte * n` pads; every field gets an
  `assert Name.f.offset == <off>` and a `sizeof` check at import.
  `rec:{…}` nested fields become synthesized `_<Parent>_<field>`
  Structure classes.
- `Typedef` → `Name = <ctypes type>` alias.
- `EnumConst` → `NAME = <int>`.
- `Function` → `_lib.<name>.argtypes = […]` + `.restype`, then a
  `def <name>(…)` wrapper returning `(True, result)` / `(False,
  ctypes.get_errno())` when `errno_guard` — `NULL`/falsy for
  pointer returns, `< 0` for integers. `out_struct:`/`in_struct:`/
  `io_struct:` descriptors become `ctypes.POINTER(<Port>Msg)` where
  `<Port>Msg` is synthesized from the inline field list, same as the
  Handl emitter's `Msg` shapes.
- Descriptor → ctypes: `i8`…`u64`→`c_intN`/`c_uintN`, `isize`/`usize`→
  `c_ssize_t`/`c_size_t`, `f32`/`f64`→`c_float`/`c_double`,
  `void`→`None`, `cstr`→`c_char_p`, `io_scalar:<t>`→`POINTER(<t>)`,
  `rec:`/`out_struct:`→`POINTER(Rec)` when the record is emitted else
  `c_void_p`, `arr:<n>:<t>`→`<t> * n`, anything else→`c_void_p` (the
  ABI slot stays right).
- Docs land as `#`/docstring comments; the Handl port signature is
  stamped per function as `# handl port: <Port>: (…) -> <Ret>`.

This is a faithful C-ABI projection, not the ergonomic surface — the
Handl port/adapter pair remains that.

## The spec input (embedded-CPython shim)

`is_python_spec` matches `.yaml`/`.yml`/`.json` (kept for command-layer
pre-flight); the `python-spec` target's `PythonSpecSource` +
`PythonSpecEmitter` produce `<output>/<package>/<package>.hnl` — a module that embeds
CPython through `ffi.call` and returns output via an env var:

```yaml
package: mymod          # required — module + package name
doc: "…"                # module doc lines
library: libpython3.14.so
python_init: Py_Initialize
python_run: PyRun_SimpleString
env_get: getenv         # libc lookup for the output channel
env_get_lib: libc.so.6
env_var: HANDL_PY_OUT   # default result channel
functions:
  - name: total
    doc: "…"
    args: [{ name: xs, type: string }]   # `type` is accepted metadata;
                                         # only `name` reaches the output
    script: "import os\nos.environ[…] = str(sum($$xs$$))"
    env: OTHER_VAR      # per-function override of env_var
```

Each function emits `<name> := (args) ~> do { _ = py_init(); code :=
"…"; _ = py_run(code); get_env("<var>") }`; `$$<arg>$$` placeholders in
`script` interpolate the Handl args into the Python source string. All functions
are `export`ed. The spec path produces `.hnl` directly — no
`SdkgenModule`, no emitter — which is why `.yaml` configs under
`--config` and this input are distinct surfaces.
